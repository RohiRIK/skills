# Reader-facing editing


1. Inspect the current source and relevant role/workflow instructions before asking Rohi to repeat established context; distinguish documented capability from exercised behavior.
2. Keep hero introductions to one concise reader-facing sentence. Omit internal profile counts, roster bookkeeping, and architectural qualifications unless essential; move supporting detail below the hero.
3. Describe actual working patterns rather than forcing every task into an orchestration pipeline. Distinguish direct specialist conversations, approved specialist handoffs, and coordinator-led multi-specialist work when the evidence supports them.
4. Match headings and layout to the content: name alternatives as working patterns, not sequential steps, and allocate the full container width to the actual number of entries.
5. Recheck visual balance after removing or regrouping entries; a correct roster and successful build do not establish a readable page. Follow the visual checks in `references/verification.md`.
