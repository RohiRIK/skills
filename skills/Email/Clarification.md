# Ask when essential information is missing

## Check before asking

Read the owner’s approved voice profile, current request, relevant context, and `Policy.md` first. Do not re-ask settled preferences or information already supplied. A missing optional field does not require an interview.

## One focused batch

When an unknown materially changes the email, ask up to four questions in one batch before drafting. Ask only the unresolved items, not a fixed four-question questionnaire:

1. Purpose or missing decision: what must the recipient do, and what facts or commitments are actually authorized?
2. Recipient and tone: who is this for, and should it sound friendly, professional, or formal, if neither context nor the profile settles it?
3. Language: ask only if the requested target is genuinely ambiguous or conflicts with the established policy. English is already the default; do not ask “English or Hebrew?” on every request. Hebrew user messages and incoming threads never select the language.
4. Name/signature: if a signed draft needs an unknown sender name or language-specific spelling, ask for the exact spelling and short/full signature preference. Do not invent a transliteration or silently leave a signature placeholder when the owner can answer.

Use the host’s structured clarification tool when available, otherwise ask the focused batch in ordinary prose. Combine related choices where natural. If only one detail is missing, ask one question. Three or four real unknowns are valid reasons for three or four questions together.

## After answers

Draft with the confirmed answers; do not restart the interview. Use neutral grammatical forms unless gender matters and is actually unknown. Optional dates are omitted rather than invented. A materially unresolved deadline, decision, or identity stays a named blocker.

If the owner explicitly asks for a rough draft now, declines to answer, or is unavailable, provide an honest draft with labeled placeholders and explain what remains missing. Do not describe it as ready to send. Saving a new preference or profile still requires the owner’s approval; a clarification answer is usable for this draft but is not permission to write persistent guidance.

## Acceptance scenarios

- Known signature, greeting, English default, and complete technical facts → draft without questions.
- Hebrew explicitly requested, but its required signature spelling is unknown → ask for that exact spelling only.
- Drafting on behalf of a new person with unknown goal, audience, tone, and signature → one batch of up to four useful questions.
- “Use the other language” without a resolvable target → ask for the target language; do not guess.
- Owner requests an immediate placeholder draft → draft and label the unresolved fields rather than block.

Structural tests validate these instructions and their links, not universal model compliance.
