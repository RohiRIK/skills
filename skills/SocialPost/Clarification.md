# Ask when essential information is missing

Same approach as the Email skill's `Clarification.md`, tuned for posts.

## Check before asking

Read the owner's approved voice profile, the current request, the relevant context, and `Policy.md` first. Don't re-ask settled preferences or information already supplied. A missing optional detail does not require an interview.

## One focused batch

When an unknown materially changes the post, ask up to four questions in one batch before drafting. Ask only the unresolved items, never a fixed questionnaire:

1. **Platform and goal**: where it goes, and what readers should do or remember, if the request doesn't say.
2. **The concrete detail**: what happened, a number, a name, a before and after. Posts without one read as generated, and the skill never invents one (`Craft.md`).
3. **Disclosure**: if the post promotes anything, is there a material connection: paid, gifted, affiliate, employer (`Disclosure.md`)?
4. **Language**: only if the target is genuinely ambiguous or conflicts with the established policy. English is already the default; don't ask "English or Hebrew?" on every request. Hebrew user messages and Hebrew source posts never select the language.

Audience and register count as a question only when neither the platform, the context, nor the profile settles them. Use the host's structured clarification tool when available, otherwise ask in ordinary prose. One missing detail, one question.

## After answers

Draft with the confirmed answers; don't restart the interview. Use gender-free Hebrew forms where gender matters and is unknown. Optional details are left out rather than invented. A missing fact the post depends on stays a named blocker.

If the owner explicitly asks for a rough draft now, declines to answer, or is unavailable, give an honest draft with labeled `[placeholders]` and say what's missing. Don't call it ready to post. Saving a new preference or profile still needs the owner's approval; an answer is usable for this post but is not permission to write persistent guidance.

## Acceptance scenarios

- Platform, goal, and a concrete detail given, English default → draft without questions.
- "Write a LinkedIn post about our launch", no detail → ask for what changed for users, with one number or example.
- A promotional post with no word on payment → ask about a material connection.
- "Post it in the other language" with no resolvable target → ask for the target language; don't guess.
- "Just give me a rough draft" → draft with labeled placeholders rather than block.

Structural tests validate these instructions and their links, not universal model compliance.
